## Complete identity and proof profiles

The authoritative exact field order is frozen in `glade/contracts/crdt-recovery-codec/vectors/schema.json`, and matched by concrete typed `src/schema/{storage,admission,production}.rs`; every field is mandatory except an explicit `Option`. The source pins bind the table, producers and typed consumer. No map of arbitrary extension fields or opaque debug/serde image is accepted.

`CreationIntent` is the unsigned genesis preimage: root key, creation nonce, incarnation, private owner and resource, zone/share/Glade ID/key, declaration hash/version/CRDT shape, schema identity/hash/version, canonical parameters, engine/payload/admission/authorization/proof/recovery/retention/rejoin/corpus profiles, corpus digest/version, admission mode, storage promise, bounds/replica limits, initial signed chain base and migration generation. `SignedDescriptorBody` binds retained exact intent bytes and their computed creation-root digest. Compute intent bytes first, then root digest, then signed descriptor body; no input refers to its own computed descriptor digest.

`IdentityBinding` retains root and exact intent bytes, zone/parameters, exact declaration and schema bytes plus versions/identity, corpus identity/version/digest, proof/recovery/retention/rejoin profiles, chain base and migration generation. A host/evidence provider MUST derive and compare declaration/schema hashes against the creation intent and compare the legacy `Descriptor` engine/payload/admission/resource/mode/storage/bounds mapping. Holding share/Glade ID/key constant while changing declaration or schema bytes/version MUST fail the old identity. Codec roundtrips alone do not do this semantic validation.

The closed proof bodies are: origin certificate (instance/identity/resource, canonical origin/epoch/display name/writer key/requester/root/issuance); policy cut (root/generation/previous/window/scoped grants/revocations/admitting nodes/replica holders); offline permit (certificate/requester/key/origin/action/admitting nodes/policy generation/window/sequence range); application operation proof (exact operation bytes, certificate and signed inner permit digest); permit wrapper (signed inner permit and writer proof); local challenge and response (exact node/resource/requester/key/op/channel/nonces/window and signed challenge digest); original admission (operation/certificate/permit/policy/time/node/storage/stable receipt ID); signed inventory header and HELLO (exact peer pair/channel/session role/nonce and full inventory metadata). Challenge and response have distinct body contexts under the same local-session domain. HELLO has its distinct body context under the accepted inventory domain.

The exact signature-domain byte strings are `glade/ic3/v1/descriptor\0`, `origin-certificate\0`, `offline-permit\0`, `policy-cut\0`, `application-op\0`, `local-session\0`, `admission\0`, and `inventory\0`, each with the full `glade/ic3/v1/` prefix. The final byte is zero. `SignedRecord` carries purpose, version 1, signer digest, exact bounded body bytes and a 64-byte signature. `decode_signed_body<T>` MUST select the expected typed context/domain and reject wrong purpose/version/length; it does not authenticate bytes.

The evidence provider MUST verify genuine signatures and all instance, declaration/schema, resource, origin, operation, requester, node, channel/session and policy bindings. `verify`, `seal` and `observe` are required methods. `BoundQuery` includes the complete identity rather than relying on a resource label. Observation MUST come from the provider's injected trusted current policy and conservative time interval. `Begin.current`, transport peer authentication and unverified proof booleans cannot confer authority. Historical retained admission is evaluated against its original signed contract; fresh admission independently checks current revocation/expiry and uncertainty. Replays and forks require exact operation/proof custody, not transport identity alone.

## Complete recovery and nonrecursive floor graph

The owned codec covers all old `State`, `Recovery`, attempt/request, invocation, binding, terminal, receipt and accounting fields, not just retained operations. `ReplicaImage` additionally retains identity, generation/predecessor, prior floor, origin certificates/next sequence/previous hash/Lamport/frontier/reserved intents/original receipts, bounded observations and classifications, session challenge/response/consumption, watermark, permanent loss and configured limits.

`IssuanceFloor` retains trusted time floor, policy generation/digest, plan and invocation namespaces, next kernel effect ID, and each canonical origin's certificate/next sequence/Lamport/previous/frontier/reserved intents. `ReplicaFloor` retains store owner, external root registration/path binding, lease, monotonic sequence, selected slot/generation/digest, next attempt, invocation/guard high water, complete guard status map and optional intent. The intent includes its own advanced issuance/attempt/invocation/guard floors and exact prior/next selection. An interrupted intent with absent next slot MUST preserve those advances and guards; it MUST NOT derive maxima from an old image alone.

The image stores `prior_floor` rather than the external floor selecting that same image. Normal order is: validated prior image/floor → prepare next image with retained prior metadata → encode/hash next image → persist next-selection intent (plus floors/guards) externally → write/sync the nonselected image slot → persist/sync external selection → expose committed result. The next image digest is outside its own hashed preimage. On an interrupted selection the external current floor is independently authoritative. Recovery checks the exact intent/selection compatibility and retains advanced identities/loss; it never requires a hash fixed point.

`ReplicaRecovery` returns the image and that independently authoritative floor. `LoadResult::Validated` MUST mean the host checked cryptographic evidence, identity, owner/root/path/lease, all cardinalities/accounting, every pending effect/request and attempt phase, original terminal/receipt custody, revision histories, namespace/counter and origin-issuance coherence. A decoded Rust value is not that assertion. Structural test fixtures deliberately contain symbolic facts and some inconsistent cross-record combinations to prove no field is lost; they are not a validated physical restore witness.

A successful host MUST use stable exclusive root ownership and a trusted external floor/registration assumption, reject clones/path substitution/rollback and retain process-restart atomicity across all crash cuts. A2 supplies types and refusal only. It does not implement OS locking, synchronization, crash recovery or arbitrary rollback resistance. The existing unlink-on-drop instance lock cannot silently stand in for the stronger stable-inode/floor-root contract. Per-resource instance sessions/floors/namespaces and independent state prevent an unresolved X from imposing a shared-root CAS wait on Y.

## Owned ingress, transitions and combined reads

`begin_ingress` MUST persist a finite guard in the trusted floor before application history consumption. Raw OS buffering does not count as application consumption; parsing, payload reads, inventory interpretation and decryption revealing resource history do. Failure to persist the guard MUST refuse consumption. Each guard binds store/instance/owner/lease/peer/channel/role/base selection/caps/deadline.

The host's `receive_ingress` MUST check its issuer before constructing work. `IngressPermit` cannot be cloned or constructed by field literals. `GuardedReceive` owns the permit and supplied future; factory invocation marks started before work can escape. `Pending`/drop/cancellation never mark drained. Only ready completion returns the permit and marks the supplied work drained. The actual B/C node path MUST own and join all carrier tasks inside this future; types cannot prove that arbitrary malicious callbacks never spawn detached work.

The local `IngressAuthority` utility does not write disk and MUST only issue after the actual host's durable registration. It bounds retained guard history, rejects repeated guard IDs, refuses foreign permits before callbacks, distinguishes never-started abandonment from started settlement and refuses close while any issued guard remains outstanding. Successful durable settlement/abandonment MUST occur before the provider retires its local utility status. Unknown writes MUST retain the exact request and guard in host custody even though the caller's by-value permit has been consumed.

`checkpoint`, `settle_ingress`, `abandon_ingress` and `record_observation` return `Committed {generation,digest}`, `Unknown`, or `Refused(Fault)`. Expected external floor/generation/digest are immutable compare conditions. Refusal or unknown cannot clear a previously active guard, turn an absent terminal into noncommit or forget an obligation. The inherited storage attempt interface keeps all original bindings/terminal/fence/receipt guarantees. Both close methods MUST enforce the combined lifecycle; consumers call `ReplicaRecoverySession::close` explicitly.

An `Observation` binds exact bytes, peer/channel/guard and expected full record references. Every entry becomes a bounded retained, missing, rejected or loss obligation. Exact inventory entries include kind, origin/sequence, operation and bundle digests plus original receipt; same-slot rivals remain separate. Transfer bundles include candidate evidence, original receipts and fork/security custody. Retained terminal custody never depends on peer acknowledgement.

`reconstruct_cut` binds instance/generation/watermark/manifest and MUST return only the exact retained combined cut. Normal finite authenticated empty rounds can settle themselves. A lost guard, forgotten digest, missing/busy history or kernel sticky incomplete state cannot be cleared by a later empty/latest inventory. There is no reset method in A2. Narrow reconstructable eligibility remains that of the accepted design; unprovable earlier loss remains incomplete. Local append MAY continue subject to integrity/capacity/permission without claiming completed history.

## Exact canonical formats and bounds

Physical owned format: bytes `glade.crdt.recovery\0\x01`, followed by canonical CBOR `[root-identity, typed-value]`. A named concrete root identity is its frozen type-name text. Container identities are recursively closed CBOR arrays: `["Vec", element]`, `["Option", element]`, `["Box", element]`, `["Tuple2", first, second]` or `["BTreeMap", key, value]`, with each child itself a root identity. Exact identity equality MUST precede typed construction. No compiler/debug `type_name` is used. Generic placeholder text from the initial private candidate is now refused; no successful A2 store or live migration existed. All existing named-root, nested field and remote profile encoding bytes remain unchanged. Records use fixed increasing integer keys starting at zero in the frozen declaration order. Enum representation is `[variant-ordinal, fields...]`; sequences are arrays, optional values are null or a singleton array, maps with ordered semantic keys are strictly ordered arrays of key/value pairs. Digests are exactly 32 bytes. `Bytes` recomputes its SHA-256 from the retained bytes. Existing `Operation` uses the unchanged released canonical CBOR operation bytes.

Remote proof/profile format: a plain canonical CBOR map with key 0 = integer version 1, key 1 = exact concrete type context, and fields at keys 2 onward in the frozen order. No recovery magic or recovery array surrounds a signed body. Nested records use their fixed integer maps. `u64` and `usize` are exactly eight-byte big-endian unsigned byte strings; `usize` additionally refuses an out-of-target-range value. Signed `i64` uses canonical CBOR integers and retains the full signed range. This explicit representation preserves full unsigned counters/time values without lossy `i64` casts; all three producers derive those boundaries independently.

Decoding MUST preflight encoded byte/item/depth/name limits before allocating typed values. The allocation-free raw pass counts all outer CBOR nodes. A complete schema-aware walk then scans every typed `Operation` byte string before any typed construction; its interpreted CBOR nodes add to the same per-call item counter, names use the same cap, and its root begins one level below the containing byte string. All records, enums and container paths propagate that context, including pending State/query/candidate/transfer fields. The binary batch decoder adds interpreted operation nodes to its existing aggregate binary-token item counter, preserving its fixed minimum schema depth and original bytes. Opaque payload/proof bytes are not silently parsed as operations. Low-level `Canonical::decode_value` is an internal structural primitive without injected limits; bounded consumers MUST use the checked public decode entry points. Decoding MUST refuse tags, floats, indefinite forms, nonshort integers/lengths, invalid UTF-8, reordered/duplicate/unknown keys, wrong contexts/version and trailing/truncated data. Reencoding equality enforces exact canonical bytes. The unchanged private batch v1 has its own `glade.crdt.batch\0\x01` grammar, complete bounded decoder and first-use blob interning. Its decoder MUST charge cumulative owned expansion before each clone/container growth so repeated references cannot amplify memory past the byte budget. A max unsigned scalar is not narrowed to `usize` merely because it appears in a CBOR head.

Encode/decode are structural tools. They do not validate signature truth, current permission, terminal coherence, trusted floor or durability. These duties remain required host/evidence contracts and are intentionally refused by current node adapters.
