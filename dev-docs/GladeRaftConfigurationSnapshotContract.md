# Glade Raft Q3 configuration and snapshot contract

Date: 2026-10-03. Status: **DRAFT remediation 1 for renewed Consistency/Safety review after three initial Safety P2 findings; compiler/fixture checks and deliberately RED specifications, no Q3 implementation or production ratification**.

This refines Q3 in [the qualification plan](GladeRaftQualificationPlan.md), RA-004/005/006/009/010/011 in [the adoption contract](GladeRaftAdoptionContract.md), and retains the accepted [Q2 profile](GladeRaftPersistenceContract.md). The two gates are contract Consistency/Safety before implementation, then Code/State on actual carrier/disk/crash evidence. Q2's fixed-configuration journal MUST NOT be described as supporting membership or snapshots. [Q3 contract evidence](GladeRaftQ3ContractEvidence.md) distinguishes compiler success from intended behavioral failures.

## 1. Allocation and bounded profile

The experiment remains `proofs/raft-adoption`, outside production Glade dependencies. Nodes are the authenticated numeric fixture universe 1–4, scope 7, group 70. Initial voters are `[1,2,3]`; learner 4 joins an existing authorized group, becomes a voter through explicit joint consensus, and old voter 3 can leave. Configuration authority principals 1 and 2 are explicit trusted inputs rooted in that bound group; principal 10 has no configuration authority. These fixtures prove neither signatures nor custody/bootstrap. Discovery MUST NOT authorize membership, create a new root, repair missing storage or change configuration. No automatic elections, real transport, external effects, Byzantine or independent-machine claim is added. The private session assembly explicitly campaigns node 1 and commits the initial election noop at index 1 before it is exposed; exact-index tests use that real retained noop rather than a missing-result surrogate. Shared Create fixtures MUST use zero generation/home preconditions, with `Action::Create.home` separately choosing the new home. Every successful application setup MUST assert the complete Accepted Resource; the mere presence of a terminal Receipt is insufficient.

`glade-raft-q3-api` is a **proposed contract** package depending only on the existing application API for complete Command/Receipt/Resource values and durability API for full StoredEntry framing. No carrier, filesystem adapter or runtime type leaks into its interfaces. `CheckpointStore::load/publish` is a meaningful dyn-compatible single-writer coherent local-image boundary. `QualificationSession` is a meaningful dyn-compatible **private experiment-composition boundary**, with explicit membership, application, original-history and checkpoint operations plus deterministic harness controls. Its `submit` MAY refuse a known changed-request retry before proposal with `Error::RetryConflict`; this is a new private admission operation, not a change to Q1a `CommittedMachine::apply`, whose ordered changed-byte attempt still has a terminal Rejected receipt. Its control methods are not a production service design. `glade-raft-q3-spec` is a **proposed harness** depending only on q3-api: intentionally refusing providers and reusable deterministic consumer specifications, no hidden real adapter or permissive model. Existing roles/dependency allowlists are unchanged; these two inventory entries/edges and expanded owned-source roots require this review, not permission to relax policy to pass a checker. The remediation proposes one additional **dev-only** `glade-raft-adoption-proof -> glade-raft-q3-api` edge solely for `q3_fixture_compatibility`, exercising corrected shared Create fixtures against the unchanged existing Application. This proposed edge requires review and is recorded explicitly in the inventory; the contract does not import the implementation, no normal edge is added, and the compiler check is not Q3 algorithm evidence. No third-party dependency is added. The empty process-global exception list stays empty.

Records owns ordered configuration/application history and checkpoint semantics. StorageAdapter owns coherent local publication/recovery through the new contract. Admission/Policy supplies validated bound authority; NodeAssembly selects instances. Directory/Discovery supplies routes and cannot grant authority. This preserves [BuildEntry](GladeBuildEntry.md), the Records/StorageAdapter allocation in [architecture revision 3](arch1/GladeArchitecture.md), and [LBT-001–012](LibraryBoundaryAndTestingPolicy.md). The candidate raft-rs 0.7.0 carrier remains an experiment, not the selected production library.

## 2. Versioned identity, lifecycle and store responsibility

`GroupIdentity { scope, group, application_profile }` is portable; V2 uses application profile 2. `Instance { scope, group, node, application_profile }` additionally binds one owned local store. Both are immutable. Mutable `Configuration` carries all ConfState lists (`voters`, `learners`, `voters_outgoing`, `learners_next`, `auto_leave`) and the last successfully applied configuration index. All lists MUST be canonical sorted/unique, nodes MUST lie in the bound 1–4 universe, incoming voters MUST be nonempty, and role intersections MUST satisfy the carrier's ConfState grammar. Learners are complete-data nonvoters. The initial profile uses explicit joint transitions and `auto_leave=false`; unsupported automatic/demotion variants MUST refuse. Every voter counts as a complete-data replica, never a metadata witness.

The eventual separate V2 adapter MUST provide explicit `create_new` and `open` operations with caller-injected paths, expected immutable instance and trusted minimum revision. These are concrete composition lifecycle operations; they do not make creation authorization a storage service's responsibility. Creation MUST use exclusive creation and a held OS file lock, synchronize the new file and parent directory, and require a host-validated existing-group join/configuration intent for learner creation. A genesis authority fixture exists only at the initial experiment assembly. An empty/missing learner path is not authority for a new group. `open` MUST NOT create/initialize missing storage. Old Q2 magic/profile, empty/corrupt files, wrong instance, or a valid foreign-group snapshot MUST refuse/quarantine without rewrite/reset/automatic upgrade. Explicit local join into a NEW owned path must validate the committed existing-group intent before store creation or snapshot receipt; no destructive replacement of an old store is implied. The profile does not add a disaster-reset procedure.

`Image { term, vote, commit, applied, configuration, checkpoint, suffix }` is one coherent recoverable local cut. `Checkpoint` binds exact portable identity, original applied index/term, exact ConfState at that cut and complete versioned application bytes. Its configuration MAY precede Image.configuration when committed suffix configuration entries have been applied; the host MUST replay those entries to prove the latter, never infer it from current discovery. With no checkpoint, suffix begins at 1. With one, suffix begins exactly at checkpoint.index+1, is contiguous and contains complete original serialized Entry bytes. `checkpoint.index <= applied <= commit <= last retained index`; `Image.applied` names the complete **validated reconstructible application cut retained by the image**, not the live serving counter. A privately restored incoming snapshot candidate can temporarily lead live application; it cannot serve or emit receipts before publication succeeds. term/vote/log/snapshot boundaries must agree. Term `u64::MAX` remains reserved: startup, campaign from MAX-1, and live publication MUST refuse it before messages or receipts.

The store validates version/framing/checksum, exact immutable binding, canonical structural ConfState, revision progression, bounded counts/lengths/index arithmetic, cuts, monotonic term/commit/applied/checkpoint, same-term vote stability, original committed suffix immutability, and same-cut checkpoint immutability. It MUST allow a legitimate **same-term historical vote for a removed voter** in the authenticated bounded universe; reconfiguration MUST NOT clear/change that vote. The vote is not a membership grant. An uncommitted suffix above commit MAY be replaced/shortened, including above a compacted prefix. Each publication compares the local revision, increases it by checked one, retains exactly the supplied image and synchronizes before success. Pre-write rejection preserves a usable prior state. Once a write begins, an error is unknown and poisons the live store until explicit reopen.

Storage does NOT interpret opaque application bytes or authenticate configuration intents. A structurally accepted image is not startup/serving authorization. The host MUST validate every retained Entry/private envelope, checkpoint application syntax and complete semantic replay/cross-consistency **before** creating a serving RawNode. It MUST compare complete shared committed prefixes/checkpoint history across available configured stores where their cuts overlap; a disagreement blocks serving. Quorum loss or a missing required store is not permission to reset. A joining nonvoter is not required to already contain current state, but cannot vote/serve until its complete restoration is independently validated.

The proposed V2 physical adapter retains Q2's conservative append-only checksummed full-image journal, now with a distinct V2 magic/schema. Publication contains checkpoint and suffix together in one record; no separately switched snapshot pointer, rename protocol or destructive journal rewrite is introduced. **Raft log compaction** means suffix omission covered by a validated durable checkpoint. Old journal records remain, so this profile does not reclaim physical disk history. Every record remains validated at reopen; partial new records quarantine rather than truncate. A new physical journal rewrite/garbage collector needs a separate reviewed atomicity protocol. The initial whole-record limit remains 16 MiB; frame/header/payload together count toward it. Allocation, u64 index/term/revision arithmetic and conversions to usize MUST be checked before unsafe allocation/publication. Retention exhaustion refuses; safe evidence is never silently evicted.

## 3. Configuration intent, outcome and joint authority

`ConfigKey { scope, group, principal, sequence }` is separate from application RequestId. `ConfigIntent` retains every key field, expected successful configuration index and exact canonical change (`AddLearner`, `EnterJoint` with canonical complete target voters, or `LeaveJoint`). Exact equality binds the complete fixture intent, not a digest or sequence alone. Different configured authorities using the same sequence MUST not alias. Exact retries MUST recover the original complete `ConfigReceipt { intent, outcome, index, configuration }` before stale-cut/readiness checks, subject to current configured disclosure authority. Changed bytes under the same key MUST fail `RetryConflict` and preserve the original. Idempotent membership edits under a *different* key MAY create a distinct applied receipt; they are not the original retry.

`configure` returning `Some(receipt)` means one applied retained terminal configuration outcome. `ConfigOutcome::Accepted` means the configuration transition was applied; `Refused(reason)` means a committed, ordered intent was refused deterministically without changing ConfState. `None` is pending/unknown, including an intentionally lost reply, and MUST NOT imply noncommit. Known local preproposal refusals MAY return explicit `Unauthorized`, `WrongBinding`, `StaleConfiguration`, `IncompleteLearner`, `HomeInUse` (EnterJoint admission only) or structural/joint errors without appending; they describe this admission attempt and never prove an earlier retry did not commit. `NoQuorum` is a harness/control observation only: configure/submit for an admitted intent MUST return unknown instead of claiming noncommit. Once admitted, a changing eligibility/cut condition MUST become a retained ordered refused outcome, not an unrecorded terminal error.

A learner is admitted only by a committed bound configuration intent. CatchUp MUST transfer original complete data, policy, outcomes, tombstones, configuration and private applied-history evidence, durably persist it and apply/validate it. The same harness control MAY catch up an existing authorized voter when verifying a movement successor; it never bypasses that node's actual storage/application path. It MUST NOT set counters from caller input. The driver captures readiness only after observing actual durable storage and complete applied state through the current predecessor cut. Promotion carries a **retained private driver readiness envelope** in the configuration Entry context, containing exact group/profile, learner identity, index/term and complete applied-state witness through that cut. No public ConfigIntent field can assert readiness. Numeric fixtures stand for source-trusted observation; Q4 supplies genuine authenticated/custodied evidence.

At the actual ordered configuration index, every replica MUST deterministically verify the retained envelope against the complete predecessor state, identity and cut. A queued earlier application command makes proof-for-C stale when the configuration takes C+2; every replica retains `Refused(IncompleteLearner)`. This decision MUST NOT consult local peer availability, mutable failure flags, discovery or live storage observations during deterministic application. Local I/O failure instead stops that replica; it cannot independently reinterpret a committed transition. If the carrier configuration Entry is refused, the host MUST NOT call `apply_conf_change` with that change; it still records the refusal/applied index and correctly advances the carrier lifecycle. Accepted/refused application across this carrier path MUST be demonstrated before claiming Q3 acceptance.

EnterJoint `[1,2,4]` retains outgoing `[1,2,3]`. A data-bearing majority of **each** set is required for commitment during joint authority. Incoming-only or outgoing-only majority MUST not return an applied application receipt. Learner 4 cannot supply an old-set vote. At most one configuration transition is pending; an incompatible nested joint intent refuses. LeaveJoint is a separately authorized, committed, applied and retained intent; no implied auto-leave. Restart while joint MUST reconstruct both sets, staged learners, accepted/refused configuration outcomes and pending suffix exactly, then retain joint quorum rules. Two voters cannot progress after either loss; losing quorum never authorizes unilateral reset.

Membership/leadership MUST NOT change resource home or generation. EnterJoint removing any **current live resource home** from target voters MUST refuse `HomeInUse`; separately ordered qualified movement to a ready remaining home or retirement must precede that transition. During joint authority, placement on an outgoing-only voter remains permitted because it is still an authorized complete-data voter; this does not guarantee it can be removed afterward. At the **actual LeaveJoint predecessor cut**, every replica MUST deterministically recheck all current live resource homes against the resulting incoming voter set. A stranded home MUST produce an ordered retained `Refused(HomeInUse)` receipt, leave the entire ConfState/configuration version unchanged, and MUST NOT call `apply_conf_change` for that exit. For an otherwise valid authorized LeaveJoint intent, this home check is an ordered outcome, not a preproposal `HomeInUse` error; a preflight observation cannot replace it. A placement command queued between exit admission and application is included in the predecessor state and MUST yield the same refusal on every replica.

Joint restart retains outgoing-only placements and the refused exit. Separately ordered qualified movement to a complete ready incoming home, or retirement, permits a NEW authorized exit intent. Movement resolution MUST use the retained private driver proof of complete durable/application readiness through the actual predecessor cut; `successor_applied` alone is never proof. The movement fixture catches up the incoming successor and checks its actual observed durable/applied cut before requesting the host-verified move. Exact retry of the old terminal key MUST still return its original refusal after resolution, not retroactively accept it. Refused entries advance the applied frontier but not `Configuration.index` (last accepted configuration mutation); a new intent with a stale expected version still refuses. Retired identities retain their historical home/generation/outcomes but do not require that former home to remain a voter. No nonvoting-home product contract is invented here. Tests MUST cover initial entry home protection, both direct and admission-race placement through exit, joint restart, retirement/movement resolution and successful final exit.

## 4. Complete snapshot and original-history semantics

The application checkpoint's private versioned envelope MUST retain: exact group/profile and cut; every complete current Resource payload/home/generation/incarnation/retired flag; the full name reservation map including retired names; explicit policy/permission values and frontier; all original application Command and terminal Receipt pairs with full request namespace; all original configuration intents/envelopes and accepted/refused receipts; and **every original applied index**, including noops/configuration entries, with original serialized Entry/private readiness bytes and original result. Exact original-index replay returns typed `ReplayResult::Application(original Receipt)`, `Configuration(original ConfigReceipt)` (accepted or refused), or `Noop { original index }`. It MUST NOT conflate configuration/noop with an absent application receipt. Missing/unapplied history returns `Error::Missing`; a changed command/envelope at a retained index returns `ConflictingReplay`, regardless of its entry kind. Original receipts/intents/configurations are compared completely after snapshot/restart, alongside the actual initial noop. The replay interface amendment replaces only the draft Q3 `Result<Option<Receipt>, Error>` signature; Q1a's existing trusted application boundary is unchanged. Q3 MUST NOT quietly replace Q1a's replay contract with only latest-state/dedup lookup.

This bounded design deliberately keeps the complete application replay prefix inside snapshots even after the carrier's Raft prefix is compacted. It is redundant and unbounded until the 16 MiB rejection limit; no application-memory, startup-cost or physical disk-saving improvement is claimed. Future bounded retry/history retention needs a versioned consumer contract and safety review. Retained commands are complete numerical fixture payloads, not digests; real Glade canonical payloads remain Q4.

The host MUST replay the entire retained applied prefix with the same private deterministic application/configuration rules, then compare **all** materialized resources, name reservations, outcome original commands/indexes/results, policy and configuration against that replay. Individually plausible lists are insufficient. The checkpoint term MUST match the original Entry at its cut; ConfState MUST match the replay at that cut. Duplicate keys, gaps, changed original outcomes, inconsistent homes/generations, mismatched tombstones/policy, incomplete private movement evidence, malformed command types or valid conflicting replay histories MUST quarantine. Exact retry uses original outcomes but serving remains governed by current disclosure, including ordered revocation after the snapshot in the suffix. Missing disclosure evidence cannot become permission.

Recovery restores the checkpoint plus contiguous suffix; it first validates configuration at persisted `applied`, then replays committed-but-unapplied suffix through commit before serving, reconstructing complete outcomes/configuration and durably recording any advanced applied cut. Uncommitted suffix stays available to real Raft reconciliation and MUST NOT become application state. ConfState at snapshot, restored storage ConfState at successfully replayed current cut, HardState and Config.applied MUST be coherent; a recognized label is never sufficient. A snapshot rollback needs an independently trusted revision/cut floor, never inferred from the same rollbackable files. Without that floor a wholly valid old-image replacement remains undetectable as in RP-007; Q3 cannot claim complete RA-011 rollback exclusion.

## 5. Carrier/storage ordering and actual implementation gate

The pinned local source is raft-rs **0.7.0**, with protobuf-codec. `RawNode::propose_conf_change` encodes ConfChangeV2; `apply_conf_change` must occur only when applying the corresponding accepted committed entry. `Raft::apply_conf_change` selects simple/enter_joint/leave_joint; explicit enter-joint MUST be used for voter-set replacement, not a sequence of unsafe simple removals/additions. Carrier `pending_conf_index` suppresses overlapping configuration transitions but does not implement authority, complete learner readiness, retry outcomes or application persistence. Those remain host obligations.

`Raft::restore` may reject a stale snapshot, require follower state and require the recipient in ConfState; malformed ConfState can enter fatal carrier paths. The host MUST validate portable identity, full checkpoint grammar/replay and configuration before feeding a snapshot to RawNode. Carrier acceptance alone proves neither payload correctness nor durable installation. A valid same-index/term fast-forward path MUST still preserve required application evidence; qualification MUST exercise both actual install and fast-forward/rejection cases. Storage supplies snapshot index/term, first_index, last_index, entries and initial HardState/ConfState consistently.

For an incoming snapshot at S while live serving application is A<S, the host MUST first decode/replay/validate the snapshot into a **private candidate** application/configuration through S without exposing it or producing receipts. Its pending V2 image carries checkpoint S, reconstructible `applied=S`, configuration at S, coherent entries/HardState and commit>=S. The driver never publishes an impossible checkpoint-S/applied-A pair. For a Ready carrying that snapshot, entries and HardState, it MUST publish this **whole coherent V2 image**, synchronize it, then install the candidate and memory Storage snapshot/suffix/HardState. It then applies committed suffix entries, invokes accepted configuration changes in order, durably retains derived configuration/applied/outcomes, and only then releases messages/receipts and advances application. A failed first publication discards the unexposed candidate and stops participation; restart reconstructs only accepted physical history. LightReady commit-only changes are still durable before application/release. If any publication/application validation fails, stop the voter and emit no receipt/messages from that failed lifecycle; recovery retains unknown rather than claiming noncommit. No step/propose/campaign may interleave while a Ready is outstanding. Follow the supported Q2 Ready/advance lifecycle; a test must not invent an unsupported carrier interleaving.

When adding a learner after source compaction, a cached snapshot before the learner-add cut excludes that receiver from ConfState and MUST NOT be sent as if eligible. CatchUp MUST regenerate a complete checkpoint at the accepted learner-add cut (or another later authorized cut containing the receiver), durably publish it, and then transfer it plus any subsequent suffix. Never rewrite the old checkpoint's ConfState at its old cut. The combined witness deliberately commits an ordinary mutation after learner admission, regenerates the snapshot at the admission cut, and restores that subsequent mutation through a real suffix. Actual NodeCut.snapshot_index reports the durable received cut; it is not a public assertion of readiness. The carrier exit case MUST exercise stale cached snapshot rejection as well as valid fresh transfer.

Snapshot compaction is legal only after the complete checkpoint/cut is durably recoverable, and original receipts/envelopes remain. The full-image record is the publication boundary; before-write/partial-write/complete-write/before-sync/after-sync faults apply to snapshot+configuration+suffix together. Reopen yields the prior accepted coherent image, the complete new image, or quarantine based on actual bytes and trusted floor—never a mixed checkpoint/cursor/configuration. A poisoned instance cannot serve from its memory mirror. Both actual SIGKILL cuts and externally retained complete originals are required; modeled conformance alone cannot close this gate.

Primary implementation pointers are the locally pinned dependency's `src/raw_node.rs` (propose_conf_change, apply_conf_change, Ready/advance APIs), `src/raft.rs` (restore and apply_conf_change), `src/storage.rs` (Storage and MemStorage snapshot/cut operations), and `src/confchange` (joint configuration grammar). This is local source inspection, not a claim that upstream documentation supplies host guarantees.
